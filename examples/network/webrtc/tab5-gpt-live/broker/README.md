# GPT-Live接続用の短期トークンサーバー

端末に通常のOpenAI APIキーを入れずに、GPT-Liveへ接続するためのサンプルです。端末を認証して60秒有効・1回限りのトークンを発行し、そのトークンで受け付けたSDPをOpenAIへ転送します。音声とイベントは端末とOpenAI間のWebRTCで直接送受信します。

このトークンは本サーバーが発行するものです。OpenAI公式のRealtime用Ephemeralトークンではありません。GPT-Liveの[公式WebRTC接続手順](https://developers.openai.com/api/docs/guides/voice-webrtc?api=live)に従い、OpenAIへのセッション作成はサーバーの通常キーで認証します。

## LANで試す

Node.js 22以降、Python 3、OpenSSLを使用します。以下は`tab5-gpt-live`ディレクトリで実行してください。

まず、サーバーを動かすPCのLANアドレスに対する開発用証明書と、端末認証トークンを生成します。

```sh
python3 broker/configure.py --host 192.168.7.140
```

生成物はGit管理外の`broker/.local/`に保存します。既存の生成物がある場合は上書きしません。PCのアドレスを変えた場合は、そのアドレスを含む証明書を用意し直してください。

通常のOpenAI APIキーを含む`.env`を指定してサーバーを起動します。APIキーは本サーバーだけが使用します。

```sh
node --env-file=/path/to/.env --env-file=broker/.local/server.env broker/server.mjs
```

次に、端末用の設定を生成します。このモードでは`.env`を読み込まず、端末設定にもOpenAI APIキーを書き込みません。

```sh
python3 configure.py --ssid YOUR_WIFI_SSID \
	--broker-url https://192.168.7.140:8443 \
	--broker-ca broker/.local/ca.der \
	--broker-device-token-file broker/.local/device-token
mcconfig -dn -m -p esp32/m5stack_tab5 -t build
```

書き込み後に「開始」を押すと、端末が新しい短期トークンを取得して接続します。再接続のたびに新しいトークンを取得するため、短期トークンの期限切れによるファームウェアの再生成は不要です。発行済みトークンの期限は接続開始に対する制限で、会話中に定期更新するものではありません。

開発用CAは端末の接続先証明書の検証に使います。証明書検証を無効にする設定はありません。信頼済みの公開CAで発行したサーバー証明書を使う場合、端末の`--broker-ca`は省略できます。Wi-Fiパスワードと端末認証トークンは端末設定・ファームウェアに含まれるため、これらは引き続き秘密情報として扱ってください。

## セッション設定とツール

`session.json`がモデル、指示、音声、ツール定義を保持します。サンプルは`gpt-live-1`、Responses委譲、Web検索、`get_device_status`、`set_volume`を使用します。独自ツールを増やす場合は、このファイルに定義を追加し、端末の`tools`にも同じ名前の実装を登録してください。

サーバーモードでは、端末が指定したモデル・指示・委譲設定はサーバーへ送信しません。端末の`tools`はローカルの実行関数として使います。端末からのセッション設定上書きは拒否します。

データチャネルで許可する送信イベントは、終了、入力のミュート／再開、ツール結果の返却、Responsesの継続です。`session.update`などでサーバーの設定を変更することはできません。ツールを実行する端末は操作結果を返せるため、決済などの重要な処理の正当性は、このサンプルの端末認証だけで判断しないでください。

## 認証と終了

| リクエスト | 認証 | 用途 |
| --- | --- | --- |
| `POST /token` | 端末認証トークン | `{value, expires_at}`を発行 |
| `POST /sessions` | 発行した短期トークン | `{transport: {type: "webrtc", sdp}}`から1回だけ接続を作成 |
| `POST /sessions/{id}/hangup` | 作成応答の`broker.control_token` | そのセッションだけを終了 |

短期トークンは検証・OpenAIへの要求より前に消費します。同時送信や失敗後の再利用では、新しい有料セッションを作成しません。要求をやり直す場合は新しい短期トークンが必要です。

端末は通常、WebRTC上の`session.close`と`session.closed`で会話を終了します。その後、HTTPでも終了用トークンを使ってサーバーの管理状態を解放します。通信断や開始タイムアウトでも、セッションIDと終了用トークンを受信できた場合はHTTP終了を試みます。HTTP終了は、最終使用量の確認の代わりにはなりません。

同時セッションは8、未使用トークンは32までです。セッションは既定で最長1時間とし、サーバーが期限に達したセッションを終了します。`LIVE_BROKER_MAX_SESSION_SECONDS`で15〜7,200秒に変更できます。終了要求が失敗した場合は30秒後に再試行します。

## サーバーの運用範囲

サンプルはTLSを必須とし、要求本文・応答本文に128 KiBの上限を設けます。接続情報やトークン、APIキー、会話本文はログに出しません。ログは`token.issued`、`session.created`、`session.released`などの処理種別だけです。

CLIの既定待ち受けは`127.0.0.1:8443`です。開発用生成設定は、同じLANの端末から接続できるよう`0.0.0.0:8443`を指定します。`HOST`と`PORT`で変更できます。

認証トークンとセッションの管理情報はメモリ上にあります。SIGINT／SIGTERMでは管理中のセッションを終了してから停止します。強制終了やPCの電源断では、この処理は走りません。サーバー再起動で管理情報を失った場合は端末から会話を終了し、新しく接続してください。複数端末の個別失効やサーバー間での状態共有が必要な用途では、端末ごとの認証と永続ストアを追加してください。

## 試験

```sh
node --test broker/service.test.mjs
```

単回利用、期限切れ、同時要求、設定上書きの拒否、セッション別の終了権限、上流エラー、容量制限、停止時の資源解放を確認します。OpenAIへの通信は試験用の応答で置き換えるため、APIキーは不要です。
