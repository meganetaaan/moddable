# まえがき

`xs` は、JavaScript エンジンとして見ると小さい実装です。しかし、本書で扱いたいのは単なる「軽量な JavaScript エンジン」という説明ではありません。`xs` の本質は、マイクロコントローラ上で JavaScript を成立させるために、何を実行時に残し、何をビルド時に追い出し、どこを ROM で固定し、どこだけを RAM で可変にするかを徹底的に設計しているところにあります。

ブラウザや Node.js を使っていると、JavaScript は「ソースを読み、実行時に初期化し、必要なら JIT が最適化する」ものだと感じやすいでしょう。ですが `xs` では、その感覚をかなりの部分で捨てる必要があります。ソースをデバイス上で毎回読まないのは普通ですし、起動前にほぼ完成しているオブジェクト世界を ROM に焼き込むのも普通です。`eval` や `Function` のような機能は、便利だから残すのではなく、ROM 予算に見合うかで判断されます。

## 本書の目的

本書の目的は、次の三つです。

1. JavaScript エンジン一般に共通する仕組みを、Web エンジニアの用語感覚でつかむことです。
2. その一般論の上で、`xs` がどこを変え、なぜそうしているのかを理解することです。
3. その理解を、組み込み JavaScript 開発の実践原則に結びつけることです。

本書では、API の列挙やサンプルコードの断片だけで理解した気にならないことを重視します。`preload` を使うと起動が速くなる、という表面的な話だけではなく、なぜ速くなるのか、代わりに何が制約になるのか、どんなコードは preload に向き、どんなコードは向かないのかまで掘り下げます。

## 実装を読む姿勢

本書では実装をたびたび参照します。ただし、読み方には優先順位があります。

1. まず概念を理解します。
2. 次に、どのファイルがその概念を担っているかを知ります。
3. 最後に、短い抜粋を見て「本当にそうなっている」ことを確認します。

実装読解の節では、長いコードを追い回すことはしません。代わりに、読む価値の高い関数や構造体を絞り込みます。実装を全部読むのではなく、「設計判断が埋め込まれている場所」を読むためです。

## 本書の前提

本書のサンプルや説明では、主に次の前提で話を進めます。

- JavaScript の基本構文は理解している
- ES Modules、Promise、`async` / `await` を日常的に使っている
- ブラウザ、Node.js、バンドラ、npm エコシステムに慣れている
- C 言語は専門でなくてもよいが、ポインタや構造体の概念には抵抗がない

逆に、マイコン開発経験はなくて構いません。本書の大半は、そこにあるギャップを埋めるために書かれています。
